# Contributing to EduMesh

Contributions to EduMesh should follow a structured development workflow.

## Contribution Guidelines

1. Understand the existing project structure before making changes.
2. Create a separate branch for new features or bug fixes.
3. Follow consistent naming conventions.
4. Write readable and maintainable code.
5. Test changes before committing.
6. Avoid committing environment files or sensitive credentials.
7. Use meaningful commit messages.

## Commit Message Convention

Use clear commit messages that describe the purpose of each change.

Examples:

- feat: add user authentication
- fix: resolve resource submission validation
- docs: update project documentation
- refactor: improve API structure
- test: add quiz API tests

## Code Quality

All contributions should aim to maintain consistency, readability and reliability across the project.
